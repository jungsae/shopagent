# 3단계 1차 체크포인트 (2026-10-23)

3-1 구현과 CPU 검증을 마쳤다. 실제 GPU smoke는 사전 검사에서 차단되어 미완료다. 3-2 전체 실행은 하지 않았으며 이 체크포인트에서 멈춘다.

## 환경과 설치

패키지는 `~/llama.cpp/bench/shopagent/.venv`에만 설치했다. Python 3.12.3, 기존 uv 사용. 설치 목록은 [requirements.lock.txt](requirements.lock.txt)에 44개 전체 버전을 보존했다. `python3 -m venv`의 ensurepip 부재 때문에 uv로 venv를 만들고 `uv pip freeze --python shopagent/.venv/bin/python`으로 고정했다.

| --- | --- |
| langgraph | 1.2.16 |
| langchain-openai | 1.7.2 |

주요 간접 의존성은 langchain-core 1.7.0, openai 3.37.0, pydantic 2.14.1, httpx 0.28.1이다. langgraph-prebuilt 1.1.1은 langgraph 의존성으로 설치됐지만 그래프 구현에서 prebuilt helper를 사용하지 않는다. 설치 캐시는 `/tmp/shopagent-uv-cache`로 지정했다.

DB는 고객 7명, 상품 20개, 주문 25개, 결제 25개, 정책 12개다. 고정 기준일은 2026-10-22 Asia/Seoul이다. 주문/환불 변경, 영수증, 상담원 접수 모두 mock DB에서만 동작한다. DB는 시나리오마다 복사하고 patch/fault를 적용한다. get_order는 의도적으로 타인 주문도 반환한다.

그래프는 설치된 LangGraph core 소스의 StateGraph, 조건부 edge, Command API를 확인해 구성했다. 턴당 8 step, tool 호출 6회, supervisor 재전환 1회로 제한한다. 답변은 ChatOpenAI의 로컬 `/v1` 연결에서 temperature 0으로 스트리밍한다. 금지 행동을 강제로 숨기지 않고 trace와 채점에 남긴다. 취소/환불/교환 등의 도구는 정책 위반을 오류로 거부하며, 실제 변경과 거부된 호출을 구분한다.

kotest/runtime.py, metrics.py, decision_models.py, route_answer.py는 sys.path import로 재사용했다. kotest 파일은 수정하지 않았다. 기존 결과/보고서에 덮어쓰지 않았고 commit/push, Docker/Windows 상태 변경, 모델 다운로드, llama.cpp 재빌드도 수행하지 않았다. Windows 명령은 지정된 읽기 전용 GPU Get-Counter 시도뿐이다.

## LangSmith

`~/.config/shopagent/langsmith.env`가 있어 Python의 splitlines/KEY=VALUE 파싱으로 로드했다. 마지막 줄 무개행 처리를 unit test로 확인했다. Project는 `LANGSMITH_PROJECT=shopagent`다. API key 값은 보고서/로그/trace에 넣지 않았다.

실제 smoke는 추론 전 차단되어 업로드 run **0개**, 업로드 시도 **0회**다. 로그에 업로드 오류는 없지만, 실제 업로드 성공이나 인증 유효성은 검증하지 못했다. 원격 결과가 존재한다고 해석하면 안 된다. 최초 초기화 때 agent 목적지와 project 중복 경고가 콘솔에 출력됐다. 요청한 project를 우선하도록 현재 프로세스에서 agent 목적지 환경 변수 2개를 제외했다. 이후 실제 env 재초기화 확인은 `enabled=true, project=shopagent, warnings=[], errors=[], runs=[]`였다. 설정 파일 자체는 변경하지 않았다.

정상 실행 시 시나리오/턴/LLM/도구를 명시적으로 업로드하고 모든 run에 config, repeat_index, scenario_id metadata와 태그를 붙인다. 초기화/업로드/read-back/flush 오류를 격리하고 키를 마스킹한다. Embedding과 환경 변수는 원격 payload에 포함하지 않는다.

## 부분 offload 및 다음 단계 조건

GPU 사전 검사와 공유 메모리 카운터가 정상인 환경에서 calibration과 같은 3개 smoke의 실제 추론을 확인해야 한다. 사용자가 검토 후 3-2를 지시하면 g12-native의 전체/동일 부분 offload 두 측정과 clef-g12/pplx-g12/jev-g12 각 1회를 config별 순차 상주 방식으로 진행한다. 이번에는 실행하지 않았다.

## 남은 한계와 종료 확인

확인 질문/카드 요청/삽입 지시 표식/금액·날짜 근거성은 정규식 기반이다. 날짜 표기 변형과 경고 목적의 공격 문구 인용 등에서 오탐/미탐이 있을 수 있다. Gold는 합성 정책에 대한 단일 작성자의 설계이며 이 단계에서 실제 모델의 성공률을 검증하지 못했다.

시작 전과 smoke 종료 시 llama-server 목록은 모두 비어 있었다. 최종 별도 `ps -C llama-server` 검사도 **잔존 0개**였다. 서버를 하나도 시작하지 않았으므로 종료할 소유 서버도 없었다. 이 상태에서 review_scenarios.md와 trace 검토를 위한 1차 체크포인트에 정지한다.
